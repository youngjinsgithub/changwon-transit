# STCIS 정류장별 시간대별 승하차 데이터 수집 가이드

> **목적:** TAGO 정류소·노선 마스터 위에 STCIS 의 시간대별 승하차 데이터를 얹어
> 창원 대중교통 EDA · 공간 분석을 수행한다. 본 가이드는 **팀원 4명** 이 12개 우선순위
> 노선을 분담하여 STCIS 데이터를 수집·정리하는 절차를 정의한다.

---

## 1. 왜 12개 노선만?

창원 전체 노선은 167개. 전부 다루면 노이즈가 많고 분담도 어려워 다음 기준으로 12개를 선정:

- **중요도 점수 상위** (`importance_score = n_stops × type_weight + n_districts × 10`)
  좌석버스 ×3, 간선버스 ×2, 지선버스 ×1, 마을버스 ×0.5
- **공간적 비중복**: 이미 선택된 노선과 통과 행정동 Jaccard 유사도 < 0.4 인 것만 추가
- 알고리즘: [scripts/select_priority_routes.py](../../../scripts/select_priority_routes.py)
- 결과 CSV: [priority_routes_12.csv](../../processed/priority_routes_12.csv), [priority_routes_stops.csv](../../processed/priority_routes_stops.csv)

→ **창원 전 권역(마산·창원·진해)을 골고루 커버**, 동선 중복 최소.

## 3. STCIS 데이터 다운로드 절차

### 3.1 사이트 진입

1. **접속:** https://www.stcis.go.kr/wps/main.do
2. **로그인** (회원가입 필요 시)
3. 좌측 메뉴: **대중교통이용 분석지표 → 주제별 분석 → 노선·정류장 지표**
4. 상단 탭: **`정류장별 이용량`** 선택

### 3.2 화면 구성 (3개 패널)

| 패널 | 입력 |
|---|---|
| **기간선택** | 시작일·종료일 (**최대 14일** 제한) |
| **공간선택** | `시도 = 경상남도`, `시군구 = 창원시` 선택 후 **검색명**(정류장 이름) 입력 → `검색` → 팝업에서 체크박스 선택 → `선택` 버튼 |
| **정류장조회결과** (우측) | 선택한 정류장이 누적됨. ARS번호 칸으로 직접 입력도 가능하나 **STCIS 가 ARS 번호를 표시/매칭 안 해주므로 이름 검색이 정석**. |

> ⚠️ **확인된 사실 (2026-05-14):** 검색 결과 팝업의 `정류장 ARS번호` 컬럼이 `~` 로 비어있음.
> STCIS 는 ARS 번호로 매칭이 안 되므로, **반드시 정류장명 + 읍면동** 으로 식별해야 한다.

### 3.3 본인 정류장 리스트 (이름 검색용)

> [data/raw/stcis/stops_by_name_A.csv](stops_by_name_A.csv) (386행) ·
> [stops_by_name_B.csv](stops_by_name_B.csv) (283행) ·
> [stops_by_name_C.csv](stops_by_name_C.csv) (238행) ·
> [stops_by_name_D.csv](stops_by_name_D.csv) (434행) ·
> [stops_by_name_all.csv](stops_by_name_all.csv) (938행, 합본)

엑셀로 열면 시군구·읍면동 순으로 정렬되어 있음. 컬럼:

| 컬럼 | 설명 |
|---|---|
| `정류장명` | STCIS 검색명 칸에 입력할 이름 |
| `시군구` / `읍면동` | 동명이 정류장 식별용 (STCIS 팝업 컬럼과 동일) |
| **`동내동명N`** | **같은 동에서 같은 이름의 정류장이 몇 개인지** — STCIS 팝업에 똑같이 N개가 뜬다는 의미 |
| **`카카오맵`** | 클릭하면 카카오맵에서 그 정류장 핀 위치가 바로 표시됨 |
| **`네이버맵`** | 네이버맵 좌표 핀 (예비) |
| `ARS` | 참고용 (STCIS 에는 표시 안 됨) |
| `stop_id` | TAGO 노드 ID (내부 매칭용) |
| `lat` / `lon` | 좌표 (상하행 구분 확인용) |

### ⚠️ 동내동명N · 방향 구분 문제

STCIS 팝업은 **ARS 가 비어있어서 같은 이름·같은 동 정류장의 방향(상/하행)을 시각적으로 구분 못함.**

| `동내동명N` | 분포 | 처리법 |
|---|---|---|
| 1 | 273개 (29%) | 1개만 있음 → STCIS 팝업의 단일 row 체크 |
| 2 | **640개 (68%)** | 상행/하행 페어 → **팝업의 동명 row 2개 모두 체크** |
| 3~6 | 25개 (3%) | 환승 거점 근처 등 — 더 신중히 확인 |

> **원칙: STCIS 팝업에서 (정류장명, 동) 으로 매칭되는 모든 row 를 체크.**
> 방향 구분은 분석 단계에서 좌표 매칭으로 처리한다 (직접 손으로 가르려고 하지 말 것).

### 📐 분석 단계의 방향 매칭 (참고)

STCIS 다운로드 결과는 정류장당 한 row 일 가능성이 높음. 그 경우:
- 우리 DB 의 `stop_id` 와 1:1 매칭이 안 되어 (동명 N개 중 어느 것인지 불명)
- **(정류장명, 동) 수준으로 데이터를 집계**해서 분석에 사용 (방향 합산)
- 또는 STCIS 응답에 좌표가 포함되어 있으면 좌표 거리로 매칭

→ 이건 데이터 받은 후 결정. 일단 **수집 단계에서는 누락 없이 다 받는 것** 이 우선.

### 3.4 이름 검색 워크플로

1. 검색명 칸에 정류장명 입력 (예: `회산교`)
2. `검색` → 팝업에 매칭 결과 (같은 이름의 상행·하행 + 동명이 다른 정류장 포함)
3. **시군구 + 읍면동** 으로 본인 CSV 와 비교, 해당 행만 체크박스 선택
4. `선택` 버튼 → 우측 정류장조회결과에 누적
5. 다음 정류장명으로 반복

> **팁:** 정류장명이 짧은 경우 (예: `시청`) 결과가 수십~수백 건 나오니, `읍면동` 으로 1차 필터하거나
> 검색명 칸에 `창원시청`처럼 더 구체적으로 입력. 어차피 우리 CSV 가 정렬되어 있어 같은 읍면동
> 묶음을 한꺼번에 검색하면 효율 좋음.

### 3.5 ARS 번호로 직접 입력해보고 싶을 때 (예비)

[ars_list_A.txt](ars_list_A.txt) 등 ARS 텍스트 파일은 그대로 둠. STCIS 가 차후 ARS 매칭을
복원하거나 다른 입력 방식이 생기면 그때 사용.

### 3.6 14일 제한 → 한 달치 = 2회 조회

| 회차 | 시작일 | 종료일 |
|------|--------|--------|
| 1차 | 2026-04-01 | 2026-04-14 |
| 2차 | 2026-04-15 | 2026-04-30 |

정류장 리스트는 **2회 모두 동일하게 재입력**해야 함. 한 번 우측 패널에 누적해놓고 그 자리에서
두 기간 모두 조회·다운로드해두는 게 효율적.

### 3.5 다운로드 후 파일 명명

본인 폴더 (`data/raw/stcis/`) 에 저장. **누가 / 어느 달 / 몇 회차** 가 드러나도록:

```
stcis_<연월>_<회차>_<담당자>.csv
  예) stcis_202604_1_A.csv   (A가 받은 2026-04 1차분, 1~14일)
      stcis_202604_2_A.csv   (A가 받은 2026-04 2차분, 15~30일)
```

> 같은 (연월, 회차) 파일을 두 명이 받지 않도록 단톡에 다운로드 시작 전 공유.

## 4. 기간 분담 — 1년치 분기 분담

위 절차를 모든 정류장에 대해 12개월 반복은 너무 무겁다. 4명이 **분기별로 나눠** 받는다:

| 담당 | 다운로드 기간 | 회차 수 |
|------|----------------|---------|
| A | 2025-01 ~ 2025-03 (Q1) | 6회 (월×2) |
| B | 2025-04 ~ 2025-06 (Q2) | 6회 |
| C | 2025-07 ~ 2025-09 (Q3) | 6회 |
| D | 2025-10 ~ 2025-12 (Q4) | 6회 |

**핵심:** 각자 본인 분기 **12개 노선이 경유하는 전체 ARS = 938개** 를 조회 — 그래야 나중에
합칠 때 정류장 누락 없이 모든 노선·기간이 다 채워진다.

> 합본 ARS 리스트: 4명 ARS 를 합쳐 dedup 한 [ars_list_all.txt](ars_list_all.txt)
> (938개, 자동 생성). 본인 분기를 조회할 때 이 파일을 통째로 사용.
> (4명 합 1,341 ≠ dedup 938: 12개 노선이 마산·창원 시내 공유 정류장 403개에서 겹치기 때문.)

**또는** (단순 분담안) 각자 본인 ARS 만, 1년치 6회씩 — 노선별로 깔끔히 분리되지만
정류장이 노선 간 공유될 때 중복 다운로드 발생. 팀에서 결정.

## 6. 데이터 포맷 (예상)

STCIS CSV 는 일반적으로 **와이드 포맷**:

| 정류장ID | 정류장명 | 일자 | 00승 | 00하 | 01승 | 01하 | … | 23승 | 23하 |
|----------|----------|------|------|------|------|------|----|------|------|
| CWB379000001 | … | 2024-01-01 | … | … | … | … | … | … | … |

→ `src/etl/stcis_loader.py` 에서 `boarding_data(stop_id, date, hour, boarding, alighting)`
로 변환·적재.

정류장 ID 가 STCIS 와 TAGO 사이에서 다르면 매칭 단계 필요 (그땐 [data/raw/stops/](../stops/)
의 국토부 CSV 가 보강용으로 등장 — TAGO 누락 777개 정류장 대비).
